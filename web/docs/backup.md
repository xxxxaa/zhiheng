# S3 备份与恢复

在“数据备份”填写 HTTPS Endpoint、Bucket、Region、前缀、Access Key ID 和 Secret Access Key，可选临时 Session Token。支持 Path style 和 Virtual hosted style，仅本机测试可用 HTTP。

先设置至少 10 字符的备份口令，再保存连接。凭据加密存本机，口令只留在内存。重开页面后输入口令并“解锁已存连接”。遗忘口令无法恢复旧文件；更换口令后，旧文件仍需要旧口令。

权限仅需指定前缀的 PutObject 与 GetObject，不需要列举或删除权限。恢复时从最近备份记录或存储控制台复制对象键。存储桶 CORS 需允许 App 准确来源：

```json
[{"AllowedOrigins":["https://your-app.example"],"AllowedMethods":["GET","PUT"],"AllowedHeaders":["*"],"ExposeHeaders":["ETag"],"MaxAgeSeconds":3600}]
```

App 中提供当前来源的可复制示例。网络错误时检查 Endpoint、CORS、区域、权限和密钥有效期。成功必须经过上传后的 GET 读回与解密验证。

默认间隔 24 小时，可设 1–168 小时。页面打开、在前台、已解锁时每分钟检查；恢复前台也检查。关闭期间不执行，重开并解锁后补做。失败至少等 5 分钟再试。Web Locks 支持时防止多个标签同时执行，否则各页面独立防重入；唯一对象键避免覆盖。

保存连接时，配置与加密凭据在同一事务中更新。更换 Endpoint、Bucket、Region、前缀或路径形式会重置本机的最近备份记录，使新目标按首次备份处理；只调整间隔则保留原成功时间。重新保存后，其他页面的旧解锁状态失效。已开始传输的旧任务可能在原目标留下加密文件，但其完成或失败不能覆盖新连接的状态；原目标文件不会被删除。

备份为 AES-256-GCM 加密的 .zhb，包含账户、持仓、偏好、每日快照和 AI 记录，不含 API Key、S3 配置或设备锁。

恢复步骤：

1. 输入口令，选择本地文件或从 S3 下载。
2. 自动校验加密完整性、版本、日期、重复 ID、账户引用，预览记录数量。
3. 确认后单事务替换数据，保留一个本机恢复前快照。
4. 核对净资产和持仓；必要时使用“撤销上一次恢复”。

加密后的备份文件最大 30 MB，CSV 最大 5 MB。导出与上传前会计算包含加密和 Base64 编码开销的文件大小，超限不会生成一个无法恢复的文件。云端下载及上传读回也按实际接收字节限制大小，不依赖服务是否返回准确的 Content-Length。

AI 分析历史不按 500 条截断；每条仍校验格式和长度，总备份受上述文件上限约束。备份失败不会修改本机账本。回退快照仍在同一浏览器，不能替代外部备份。新设备需重新配置连接和设备锁。
